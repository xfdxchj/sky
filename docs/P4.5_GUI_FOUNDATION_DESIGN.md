# P4.5 GUI Foundation

## Goal
Provide one reusable, server-authoritative menu foundation for the next SkyBlock systems. The first pass intentionally uses a single 27-slot menu layout rather than introducing a custom rendering framework or external UI dependency.

## Architecture
- `SkyBlockGui`: registers the shared ScreenHandlerType during common initialization.
- `SkyBlockScreenHandler`: owns a 27-slot read-only menu inventory; all click actions are handled on the logical server.
- `SkyBlockHandledScreen`: client-side presentation with a compact dark-blue panel and vanilla item icons/tooltips.
- `GuiMenuManager`: creates menu pages, fills display items and routes button actions.
- Per-screen action maps are copied into the server ScreenHandler. They are not held in a global player-shared map.

## Initial menu pages
- Main menu: Profile, Bank, Quests, Shop.
- Profile: player name and Purse overview.
- Bank: Purse and Bank balances.
- Quests: current quest state; clicking an unaccepted quest accepts it.
- Shop: registered offer catalogue (read-only in this milestone).

Command: `/skyblock menu`

## Security and interaction model
- The menu inventory is not a storage inventory.
- All slots reject insertion and extraction.
- Slot clicks are interpreted on the server and do not move menu icons into player inventory.
- Unknown slots and non-left-click actions are ignored.
- Quest acceptance calls the existing QuestManager, so completion and rewards remain server-authoritative.

## Build integration
Client GUI classes are stored under `src/client/java` and explicitly included in the main Java source set so Loom compiles them with Minecraft client mappings. The client entrypoint only registers the screen renderer; the ScreenHandlerType is registered in common initialization so the integrated server has the same type.

## Deliberate limitations
- Bank balances are displayed; deposit/withdraw controls are not wired yet.
- Shop catalogue is display-only; buy/sell actions remain command-based.
- No custom textures, animated widgets, pagination, search, category tabs, drag-and-drop or responsive layouts.
- The main menu currently has fixed entries and uses vanilla item icons.

# P3.3 Design — Authoritative Mob HP

## Goal
Give registered SkyBlock mobs an HP pool independent of the vanilla entity's max health, without replacing the current vanilla entity bridge or P3.1 player damage formula.

## State model
- Each entity instance is keyed by its Minecraft UUID.
- Current mob definition ID and maximum/current SkyBlock HP are persisted in dimension-scoped `PersistentState`.
- JSON definition supplies initial maximum HP for a newly encountered entity.
- Existing instances retain saved maximum/current values even if a later data reload changes the definition.

## Damage flow
1. Resolve the entity's SkyBlock mob definition.
2. For registered mobs with positive configured HP, obtain or create the persistent HP pool.
3. Synchronize vanilla health to the same current/max proportion so vanilla health bars remain useful.
4. Run the existing SkyBlock damage formula, then scale requested damage into vanilla-health units.
5. Let Minecraft's damage pipeline apply armor, invulnerability and other native mitigation.
6. Convert accepted vanilla health loss back into SkyBlock HP and synchronize the visible health bar.
7. At zero SkyBlock HP, invoke the native entity kill path, clear the HP record and grant configured rewards.

Unregistered entities continue using vanilla health directly.

## Deliberate non-goals
P3.3 does not implement custom entity classes, SkyBlock mob AI/attack damage, spawn configuration, boss bars, nameplates, drops tables or custom loot. Those are separate milestones.

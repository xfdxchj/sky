# P4.3 NPC System Design

## Goal
Add a small, data-driven NPC interaction foundation on top of P4.2 regions and warps. This milestone deliberately uses vanilla living entities as temporary visual stand-ins; it does not claim to reproduce Hypixel NPC models, skins, dialogue GUI or quest behavior.

## Data
NPC resources live at `data/skyblockrpg/skyblock/npcs/*.json`:
- `id`: stable NPC identity
- `name`: display name
- `entity_type`: registered Minecraft entity type; defaults to `minecraft:villager`
- `required_region_id`: optional region in which interaction is allowed
- `interaction_radius`: maximum squared-distance-checked interaction radius (0, 16]
- `dialogue`: ordered plain-text lines
- `action`: `none`, `bank`, `shop` or `warp`
- `action_target`: required warp ID for `warp`

Each spawned NPC receives a per-instance command tag (`skyblockrpg_npc_<id>`). The tag, not its vanilla entity type, determines its SkyBlock NPC identity, so multiple NPC definitions may use villagers without colliding.

## Runtime behavior
- NPC definitions load from datapack resources when the server starts.
- `/skyblock npc list`, `info` and permission-level-2 `spawn` are development commands.
- Right-click interaction is handled server-side through Fabric's entity-use callback.
- Tagged NPC interactions suppress vanilla entity interaction, including villager trading.
- Region restrictions check the player's current P4.2 region; they do not merely check whether the region was discovered.
- Bank action displays Purse/Bank balances and the existing deposit/withdraw commands.
- Shop action lists the existing shop catalogue and its purchase command.
- Warp action invokes the existing WarpManager, including its discovery and destination checks.

## Deliberate limitations
- NPCs are spawned manually for testing; no Hypixel map placements or production NPC coordinates are asserted.
- No custom entity renderer, skin, hologram, pathfinding, animation, dialogue screen, clickable dialogue options, quest state, schedules or natural respawn.
- Shop and bank actions reuse current command-driven services; they do not introduce separate transactions or bypass their validation.
- NPC entity persistence currently relies on the Minecraft world save. The NPC definition registry itself is reloaded from resources at server start.

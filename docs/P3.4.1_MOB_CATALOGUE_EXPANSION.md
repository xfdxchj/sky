# P3.4.1 Mob Catalogue Expansion Plan

Research snapshot: 2026-11-26  
Base branch: p3.4-mob-database-and-attacks

## 1. Why the current 58 records are not the full catalogue

The current 58 JSON files are a starter dataset, not a complete Hypixel SkyBlock mob database. Forty-five of those records are level variants from only three Private Island families (Zombie, Skeleton and Spider). The remaining records are a small selection from Hub, The Park and Deep Caverns.

The current community-maintained Bestiary page says it tracks kills for **360 mobs** across SkyBlock. This is a useful coverage benchmark, but it is not a promise that all 360 entries are ordinary hostile mobs or need the same combat implementation. Bestiary families can contain multiple named mobs and variants. We must not equate 360 Bestiary-tracked mobs with 360 independent vanilla entity types.

Reference: https://hypixelskyblock.minecraft.wiki/w/Bestiary

## 2. Catalogue scope and classification

The catalogue must cover more than ordinary overworld hostiles. Every entry should be classified along independent axes:

- category: ordinary, miniboss, boss, slayer_boss, dungeon, sea_creature, pest, passive, event, critter/hunting, or other.
- area: the island, region, dungeon, event, or activity where it appears.
- family_id: Bestiary family / logical family, not necessarily the same as the display name.
- mob_types: combat and interaction tags (undead, skeletal, animal, aquatic, arcane, construct, etc.).
- implementation_status: catalogue_only, vanilla_bridge, custom_entity, scripted_boss, or passive_only.
- data_status: verified, partial, derived, unknown, or stale.
- Provenance: source type, URL, retrieval date, game-version context, and confidence.

Do not overload entity_type: multiple SkyBlock mobs can share a Minecraft entity type, and a single family can have many variants. Entity mapping belongs to a separate spawn/adapter layer.

## 4. Import priority

### P0 — Core public-island combat coverage
1. Hub / Graveyard / Crypts / Ruins completion.
2. Spider's Den.
3. The End.
4. Deep Caverns completion.
5. Dwarven Mines.
6. The Park completion.

These areas establish the ordinary combat loop, mob families, drops, coins, Combat XP, and Bestiary progression.

### P1 — Progression regions
1. Crystal Hollows.
2. Crimson Isle ordinary mobs and minibosses.
3. Catacombs regular mobs and minibosses.
4. Slayer quest mobs, minibosses and bosses.

These require category-specific reward and spawn behavior. Do not flatten bosses or Slayer mobs into ordinary mob rows.

### P2 — Activity and event catalogues
1. Sea Creatures, separated by fishing location, requirements, weight and rarity.
2. Garden Pests, with spawn/capture rules and drops.
3. Kuudra encounter mobs.
4. Spooky, Jerry and other seasonal/event mobs.
5. Moonglade Marsh / Hunting and newer island content.
6. Passive animals and collection-only creatures.

## 5. Data rules

1. Import only fields supported by an explicit source. Do not infer HP, Damage, Defense, drops, spawn weights or reward values from names or vanilla entity stats.
2. Unknown numeric fields must be nullable/absent or explicitly marked unknown. A zero Defense value is not acceptable as an undocumented default in the long-term data model.
3. Keep directly listed values separate from formula-derived values. Record the formula/version when derived.
4. Keep drop probability, fishing weight, spawn chance and loot-pool weight as different concepts.
5. Store variants as distinct records only when they have distinct game identity or stats. Link them through family_id and optional variant_group.
6. Preserve original page URL and retrieval date for each imported record.
7. Community Wiki data is community-maintained, not official Hypixel API data. Mark it accordingly and lower confidence when pages are incomplete or disputed.
8. NEU repository mob files are useful for render/model metadata, not a complete source of combat stats.
9. Passive animals, Hunting creatures, Sea Creatures and Pests may share the broad Mob catalogue but must not automatically enter the hostile-combat bridge.

## 6. Required schema evolution before large-scale import

The existing P3.4 schema is sufficient for a starter combat catalogue but not for all current SkyBlock activities. Add fields in a backwards-compatible manner or introduce separate activity definitions:

- implementation_status
- data_status
- variant_group and variant_name
- reward_mode (explicit, standard_formula, special_formula, none)
- spawn_rules_ref (reference to separate spawn definitions)
- combat_profile_ref (reference to attacks/abilities)
- activity_profile_ref (fishing, pest, hunting, dungeon, event, etc.)

Avoid putting every mechanic into MobDefinition. Keep spawn tables, attack profiles, reward rules, fishing weights and event conditions in separate registries.

## 7. Definition of done for catalogue expansion

- Every Bestiary family visible in the chosen current-game snapshot has an inventory row, even if detailed stats are not yet known.
- Every imported mob record has a stable ID, family, area/category and provenance.
- Missing values are explicitly marked; no fabricated stats.
- Duplicate names and shared vanilla entity mappings are audited.
- Special systems (Slayer, Dungeon, Sea Creature, Pest, Kuudra, event) are represented separately from ordinary hostile mobs.
- A coverage report can show counts by area, category, family, and data completeness.
- This milestone is a data catalogue milestone, not a claim that every listed mob already spawns or has custom AI in-game.
